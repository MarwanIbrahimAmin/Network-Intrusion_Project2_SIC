# Network Intrusion Detector

An end-to-end machine learning project for identifying malicious network flows from tabular traffic data.

The project combines a reproducible experimentation notebook with a lightweight Streamlit application. The notebook prepares the data, compares several classifiers, and exports the selected deployment artifacts. The app then loads those artifacts to classify uploaded CSV files as **BENIGN** or **ATTACK**, display confidence scores, and export the predictions.

> **Why this project matters:** network telemetry is high-dimensional, noisy, and often incomplete. This project treats preprocessing as part of the model contract, so the data uploaded at inference time is transformed in the same way as the data used during training.

## What is included

| Component | Purpose |
| --- | --- |
| `project2_Sic_notebook.ipynb` | Data exploration, cleaning, feature engineering, model comparison, and artifact export |
| `app.py` | Streamlit inference interface for batch CSV classification |
| `deployment_artifacts/` | Serialized XGBoost model and preprocessing metadata used by the app |
| `samples/sample_test_unlabeled.csv` | Small example input that can be uploaded directly |
| `make_sample.py` | Utility for generating a balanced sample from `combinenew.csv` |
| `requirements.txt` | Runtime and notebook dependencies |

## Technical workflow

```text
Raw network-flow CSV
        |
        v
Column normalization and invalid-value handling
        |
        v
Negative-value masking + median imputation
        |
        v
Mutual-information feature selection
        |
        v
Standard scaling
        |
        v
XGBoost binary classifier
        |
        v
BENIGN / ATTACK + attack probability
```

### Training and preprocessing

The training workflow in the notebook:

1. Removes duplicate rows and duplicate columns.
2. Normalizes column names and converts common placeholders such as `?`, `unknown`, and `None` to missing values.
3. Masks invalid negative values in network-flow measurements that should be non-negative.
4. Creates a binary target: `0` for `BENIGN`, `1` for every attack category.
5. Splits the data with stratification.
6. Fits a median imputer on the training data.
7. Selects the top 40 features using mutual information.
8. Standardizes the selected features.
9. Uses SMOTE only on the training split to address class imbalance.
10. Compares multiple models and exports the XGBoost model for deployment.

The exported preprocessing objects are loaded by the application rather than recreated at prediction time. This prevents training/inference drift and preserves the exact feature order expected by the model.

## Run the application locally

### 1. Create an environment

```bash
python -m venv .venv
source .venv/bin/activate
```

On Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

### 3. Start Streamlit

```bash
streamlit run app.py
```

Open the local URL shown by Streamlit, upload a compatible CSV, and review the predictions in the results table.

## Input data contract

The application accepts a CSV containing the raw network-flow feature columns used during training. It automatically:

- strips whitespace from column names;
- handles infinities and common missing-value placeholders;
- ignores training-only columns when present: `Label`, `Binary_Label`, `RST Flag Count`, and `Destination Port`;
- validates that all selected model features are available;
- returns an explicit error when required features are missing.

The included example can be used as a quick smoke test:

```text
samples/sample_test_unlabeled.csv
```

The app produces:

- `Prediction`: `BENIGN` or `ATTACK`;
- `Attack_Probability`: the model probability for the attack class;
- a downloadable `predictions.csv` containing the original input columns plus the results.

## Rebuild the deployment artifacts

The committed artifacts were generated by the notebook. To retrain or regenerate them:

1. Obtain the source network-flow dataset.
2. Place the prepared combined file at the notebook's expected path, `combinenew.csv`.
3. Run `project2_Sic_notebook.ipynb` from top to bottom.
4. Confirm that these files have been refreshed:

```text
deployment_artifacts/
├── imputer.pkl
├── non_negative_cols.json
├── scaler.pkl
├── selected_features.json
└── xgb_model.pkl
```

For a small upload sample generated from the source dataset:

```bash
python make_sample.py
```

## Design decisions

- **Binary operational target:** collapsing attack families into `ATTACK` makes the deployed tool useful as a first-line detection signal while keeping the interface straightforward.
- **Feature selection before deployment:** the app uses the same selected feature list and ordering saved during training, avoiding accidental dependence on unused columns.
- **Artifact-based inference:** the model, imputer, scaler, and feature metadata are versioned together so the application remains reproducible.
- **Batch-friendly output:** the interface is designed for CSV-based traffic exports and returns both human-readable summaries and machine-readable results.

## Project status and limitations

This repository is a practical prototype for batch network-flow classification, not a complete production SOC platform. Before production use, consider:

- validating performance on a temporally separate and organization-specific dataset;
- monitoring class drift, calibration, false positives, and false negatives;
- adding model and artifact versioning;
- securing uploads and enforcing file-size limits;
- adding authentication, audit logging, and automated tests around the preprocessing contract.
